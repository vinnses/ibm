## HR-W031-001 — Tailnet authorization and observed Funnel URL

- **Related gap:** the current environment has neither an authorized tailnet credential nor a Docker runtime, so it cannot observe the registered node, approve the tailnet policy, or obtain the allocated public URL.
- **Why agent work is insufficient:** W031 has no tailnet credential or administrative authority, and no secret may be added to the repository. The public DNS name is allocated from the real tailnet domain and must not be invented.
- **Human action/question:** can an authorized Tailscale Owner, Admin, or Network admin register the persistent `ibm` node, approve tailnet HTTPS/Funnel policy if prompted, run the documented Funnel activation, and record the URL actually returned by Tailscale?
- **Required response provenance:** sanitized output from `tailscale status --json` showing the self hostname `ibm`; `tailscale funnel status` showing a proxy to `http://127.0.0.1:3000`; successful HTTP response from the printed public URL. Do not preserve auth keys, cookies, or tokens.
- **Gate consequence:** this blocks only authenticated node observation, end-to-end Funnel verification, and recording the actual URL. It does not change the static stack, SvelteKit build, local endpoints, secret handling, or persistence design.
- **Status:** open pending execution on an authorized Docker host and tailnet.
