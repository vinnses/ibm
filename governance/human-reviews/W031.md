# W031 — Human review questions

## HR-W031-001 — Tailnet authorization and observed Funnel URL

- **Related gap:** the current environment has no authorized tailnet credential, so it cannot observe the registered node, approve the tailnet policy, or obtain the allocated public URL.
- **Why agent work is insufficient:** W031 has no tailnet credential or administrative authority, and no secret may be added to the repository. The public DNS name is allocated from the real tailnet domain and must not be invented.
- **Human action/question:** can an authorized Tailscale Owner, Admin, or Network admin register the persistent `ibm` node, approve tailnet HTTPS/Funnel policy if prompted, run the documented Funnel activation, and record the URL actually returned by Tailscale?
- **Required response provenance:** sanitized output from `tailscale status --json` showing the self hostname `ibm`; `tailscale funnel status` showing only the `tcp://web:3000` backend; successful HTTP response from the printed public URL. Do not preserve auth keys, cookies, or tokens.
- **Gate consequence:** this blocks only authenticated node observation, end-to-end Funnel verification, and recording the actual URL. It does not change the static stack, SvelteKit build, local endpoints, secret handling, or persistence design.
- **Status:** open pending authenticated execution on the authorized tailnet.

## HR-W031-002 — Host reboot after kernel replacement

- **Related gap:** Docker 29.7.2, Compose 5.5.1, and Buildx 0.36.1 were installed while the running kernel was `7.2.2-1-cachyos` and its module tree had been replaced by `7.2.3-1-cachyos`.
- **Why agent work is insufficient:** loading the required `bridge`, `veth`, and `overlay` modules requires booting the installed kernel. Restarting the shared workstation can interrupt unrelated user applications and therefore requires explicit coordination.
- **Human action/question:** authorize and perform a controlled host reboot, then return to W031 so the primary session can start Docker and execute the full runtime/security validation.
- **Required response provenance:** post-reboot `uname -r`, active `docker.service`, and successful disposable-container/network checks.
- **Gate consequence:** this previously blocked Docker image build, Compose startup, container/network hardening inspection, and local Tailscale daemon checks.
- **Status:** resolved; the user performed the coordinated reboot, the host now runs `7.2.3-1-cachyos`, Docker is active, required modules load, and runtime validation completed.
